# Matriz Comparativa: Derechos del Titular de Datos

> **LegalSkillsLATAM** — Matriz de referencia normativa. No constituye asesoría jurídica.
> Versión: 1.0.0 | Última actualización: 2026-06-02

Esta matriz compara los derechos que los titulares de datos personales tienen en cada jurisdicción, los plazos de respuesta obligatorios y las particularidades más relevantes para el diseño de sistemas.

---

## Resumen Ejecutivo para Devs

Si operas en múltiples países LATAM, **diseña tu sistema de respuesta a derechos con el plazo más corto** (10 días hábiles de Ecuador o Colombia) como estándar base. Así cumples con todos.

| Jurisdicción | Plazo Respuesta | Marco | Multa por incumplimiento |
|---|---|---|---|
| 🇨🇴 Colombia | **10 días hábiles** | ARCO | Hasta 2,000 SMLMV (~USD 750K) |
| 🇲🇽 México | **20 días hábiles** | ARCO | Hasta 320,000 días de SMG (~MXN 34M) |
| 🇧🇷 Brasil | **15 días** | LGPD Art. 18 | Hasta R$ 50M por infracción |
| 🇨🇱 Chile | **2 días hábiles** (confirmación) + **5 días** | Ley 19.628 | En actualización (nueva ley) |
| 🇦🇷 Argentina | **30 días hábiles** | ARCO | Hasta ARS 3M (en revisión) |
| 🇵🇪 Perú | **20 días hábiles** | ARCO | Hasta 100 UIT (~USD 120K) |
| 🇪🇨 Ecuador | **15 días hábiles** | ARSOP | Hasta 1% ingresos por infracción leve |
| 🇪🇺 GDPR | **30 días** (extensible +60) | GDPR Cap. III | Hasta €20M o 4% facturación global |
| 🇺🇸 CCPA | **45 días** (extensible +45) | CCPA/CPRA | Hasta USD 7,500 por violación intencional |

## Implicaciones Técnicas para el Sistema de Derechos

Para construir un sistema de gestión de derechos de titulares (DSAR — Data Subject Access Request), considera:

### Esquema de base de datos mínimo recomendado

```sql
CREATE TABLE dsar_requests (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id       UUID REFERENCES users(id),
  request_type  VARCHAR(30) NOT NULL, -- 'access','rectification','deletion','opposition','portability'
  country       CHAR(2) NOT NULL,     -- 'CO','MX','BR','CL','AR','PE','EC','EU','US'
  status        VARCHAR(20) NOT NULL DEFAULT 'pending', -- 'pending','in_review','completed','rejected'
  received_at   TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  deadline_at   TIMESTAMPTZ NOT NULL, -- calculado según país
  completed_at  TIMESTAMPTZ,
  rejection_reason VARCHAR(500),
  notes         TEXT,
  created_by    UUID,                 -- operador que registró la solicitud
  updated_at    TIMESTAMPTZ DEFAULT NOW()
);

-- Índice para monitorear solicitudes próximas a vencer
CREATE INDEX idx_dsar_deadline ON dsar_requests(deadline_at) 
  WHERE status IN ('pending', 'in_review');
```

### Lógica de cálculo de deadline por país

```javascript
function calculateDeadline(country, requestType, receivedAt) {
  const deadlines = {
    CO: { business_days: 10 },
    MX: { business_days: 20 },
    BR: { calendar_days: 15 },
    CL: { business_days: 5 },
    AR: { business_days: 30 },
    PE: { business_days: 20 },
    EC: { business_days: 15 },
    EU: { calendar_days: 30 },
    US: { calendar_days: 45 }
  };
  // Implementar lógica de días hábiles según país (excluir feriados locales)
  return addDays(receivedAt, deadlines[country]);
}
```

### Alertas recomendadas

- ⚠️ **T-5 días**: Alerta al equipo responsable de DSAR
- 🔴 **T-2 días**: Escalamiento a legal/compliance
- 🚨 **T+0 (vencimiento)**: Registro de incumplimiento + notificación a dirección
